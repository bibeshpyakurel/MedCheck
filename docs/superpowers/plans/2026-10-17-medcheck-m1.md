# MedCheck M1 (Demo Flow) Implementation Plan

> **For agentic workers:** Each workstream (A–F) is executed by one subagent in its own git worktree, on branch `feat/<workstream>` off `origin/dev`, ending in one PR into `dev`. Steps use checkbox (`- [ ]`) syntax. Pure logic is test-first (superpowers:test-driven-development).

**Goal:** The full 8-step demo from the spec works end to end on the `dev` preview.

**Architecture:** Next.js 16 App Router pages and route handlers over the M0 data layer (`src/lib/records.ts`, `src/lib/catalog.ts`) and contract (`src/lib/domain/schema.ts`). Pure checks in `src/lib/checks`. Gemini via AI SDK for photo and description extraction.

**Tech Stack:** Next.js 16.4, React 19.3, Tailwind 4, shadcn/ui (Base UI), Supabase (`@supabase/ssr`), AI SDK 7 + `@ai-sdk/google`, `@zxing/browser`, `@react-pdf/renderer`, Resend, Vitest 5.

**Spec:** `docs/superpowers/specs/2026-10-17-medcheck-design.md`. Also read `AGENTS.md` (boundaries, code map, conventions).

## Global Constraints

- Evidence, not advice: no dose/volume/schedule calculation, no "safe", no picking the right bottle, children's tables in full with no highlighted row.
- `no_finding` copy: "No … found in confirmed fields". Status colors: `finding`, `unresolved` tokens; no green for no_finding.
- AI values are `pending` until the user acts; `pending`/`unknown` → dependent checks `unresolved`.
- "I already gave both": reuse `src/components/already-gave-both.tsx` unchanged.
- Do not edit `src/lib/domain/schema.ts`, `src/lib/records.ts`, `src/lib/catalog.ts`, `src/lib/domain/fields.ts` except small additive exports (new functions/types) that you call out in the PR body.
- Base UI shadcn: `render` prop, no `asChild`.
- Phone-first, works at 1280px; tap targets ≥ 44px; light + dark.
- Migrations: you may add a file with `npx supabase migration new <name>`, but **never run `supabase db push`** — the coordinator applies migrations after merge. Never run `npm run db:types` against a changed schema; hand-add types only if you added a migration, and say so.
- Never commit secrets. Copy env with `cp /Users/bibeshpyakurel/orca/workspaces/MedCheck/initial-implementation/.env.local .env.local`.
- Before opening the PR: `npm run lint && npm run typecheck && npm test && npm run build` all pass.
- PR into `dev` only (`gh pr create --base dev`), body ends with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`; commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Route and ownership contract

| Route | Owner | Notes |
| --- | --- | --- |
| `/` | D | Landing; CTAs "Try the demo household" / "Start my own" |

| `/patients/[patientId]/add/pick` | A | Catalog list → draft entry from catalog (`inputMethod: "picker"`) → review |
| `/patients/[patientId]/add/photo` | B | Query: `kind` (SourceDocumentKind, default `prescription_label`), optional `formulationId`, optional `method` (`photo`\|`barcode`). Upload → source doc → `/api/extract` → one draft entry per medication found → review |
| `/patients/[patientId]/add/describe` | B | Mic (MediaRecorder) or typed → `/api/describe` → draft entry (`voice`\|`typed`) → review; opens `<AlreadyGaveBoth defaultOpen/>` when detected |
| `/patients/[patientId]/entries/[entryId]/review` | B | Matches / Edit / Can't tell per field; confirm only when `isFullyReviewed`; then next draft for this patient, else record page |
| `/patients/[patientId]/entries/[entryId]` | A | Label view: confirmed strength beside label directions, 24-h max, warnings quotes, full sanitized `dosageTableHtml` |
| `/patients/[patientId]/export` | E | Preview + Download PDF + Share + Email |
| `/api/patients/[patientId]/report.pdf` | E | PDF (react-pdf), runs as user |
| `/api/patients/[patientId]/email` | E | Resend send (when configured), 5/day limit |
| `/api/ndc/[code]` | A | `{ formulation }` or 404 |
| `/api/extract`, `/api/describe` | B | Gemini |
| `/demo-kit` | F | Printable fictional labels + barcodes |

### Workstream C: The six checks, pharmacist questions, checks panel, findings UI

**Files:** Replace `src/lib/checks/index.ts`; create `src/lib/checks/{overlap,repeated,concentration,units,document-vs-bottle,database-vs-box,identity,questions}.ts` with a `*.test.ts` each and `src/lib/checks/__fixtures__/entries.ts`; replace `src/components/checks/checks-panel.tsx`; create `src/components/checks/finding-card.tsx`.

**Interfaces:**
- Consumes: schema.ts types, `isUsable`, `formatStrength`, `formatDose`, `entryLabel`, `normalizeIngredient`.
- Produces: `runChecks(input: CheckInput): CheckRun[]` (always six runs in `CHECK_IDS` order, only `status === "confirmed"` entries); `productIdentity(entry): string | null`; `mgPerMl(s: Strength): number | null`; `<ChecksPanel runs={CheckRun[]} />` (summary line "6 checks run, N found something, M couldn't be completed", each run with status badge and reasons, findings via `<FindingCard finding />`); `<FindingCard finding />` (title, detail, evidence list with document kind/date, label warning quote, pharmacist question with copy button).
- Rules (spec §6): overlap = distinct identities share a normalized ingredient (repeats excluded); repeated = same identity twice; concentration = same ingredient, liquids, different mg/mL (show both as printed, never a volume); units = dose unit vs strength unit mismatch (tsp/teaspoon vs mL, mg dose for a liquid, missing unit); document vs bottle = same ingredient across ≥2 document kinds with different strength or instructions → finding listing dates, no resolution; database vs box = barcode entries whose confirmed photo values differ from `formulations[formulationId]`.
- [ ] Tests first, at minimum: overlap NyQuil (325 mg caplet) + Calmora A → finding with warning quote; same product twice → repeated, not overlap; Bottle A vs B → concentration finding text contains "100 mg per 5 mL" and "200 mg per 5 mL" and no computed volume; strength `unknown` on one entry → concentration `unresolved` with reason naming the product; discharge 160 mg/5 mL vs bottle 100 mg/5 mL → document_vs_bottle finding; "2 tsp" vs label in mL → units finding; barcode entry photo strength ≠ catalog → database_vs_box finding; barcode entry without photo evidence → database_vs_box `unresolved`; no entries → all `not_applicable`; output never contains the word "safe".
